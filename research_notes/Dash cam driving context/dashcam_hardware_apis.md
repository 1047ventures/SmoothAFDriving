# Dash cam hardware and APIs: how a third-party iOS app can get video and event data out of consumer front+rear dash cams

Researched 2026-11-06. About 18 tool calls: web search, page fetches, and GitHub searches and README reads through `gh`.

Confidence key: **[H]** a primary source (vendor page or the code itself) confirms it. **[M]** a credible community source (dashcamtalk, an active GitHub repo) confirms it. **[L]** a single forum post or an old source. **[U]** unverified prior knowledge, written down only as a lead and not cited.

## Q1: How each brand connects. Is it Wi-Fi AP only, or can it join a phone hotspot or home Wi-Fi as a client (station mode)? Does it have 5 GHz or Bluetooth?

### Takeaway
Viofo is the only consumer brand with official, documented station mode, across almost all current models. In station mode the camera can join the phone's hotspot, so the phone keeps cellular internet while it talks to the cam. Every other brand is AP-only in its stock consumer firmware, which means the phone has to leave its normal Wi-Fi and join the camera's network. The exceptions are BlackVue (its own cloud, and STA mode in the Fleet SDK firmware) and the LTE/cloud cams (70mai A810 with its 4G module, Nexar, Garmin Vault).

### Cited Findings
- **Viofo [H]:** Viofo's official guide (dated 2025-04-11) lists Wi-Fi Station Mode on the A329 series, A229 Ultra, A229 Pro, A229 Plus, A139 Pro, A139, A119 Mini 2, A119M Pro and A129 Duo. Setup: enter the SSID and password under "Wi-Fi Station Configuration" in the Viofo app, then use a button combo (MIC+Wi-Fi on A329/A229 Pro/Plus/Ultra; REC+Wi-Fi on A139 Pro/A139/A119 Mini 2). The cam then says "Wi-Fi Connected", and live view works through `rtsp://<IP>` while files are browsable at `http://<IP>`. — [Viofo blog](https://www.viofo.com/blogs/viofo-car-dash-camera-guide-faq-and-news/how-to-enable-wi-fi-station-mode-on-your-viofo-dashcam)
- **Viofo [M]:** A user put an A229 into station mode on a phone hotspot. Viofo Support said (2023) that the official Viofo app does not work in station mode, only in AP mode. The workaround was the cam's IP in a browser plus VLC for live view. A 2026-01-31 post asks whether that has changed and links a Reddit workaround that assumes a fixed IP. — [dashcamtalk A229 RTSP + wifi station](https://www.dashcamtalk.com/forum/threads/a229-rtsp-wifi-station.49563/)
- **Viofo [M]:** Users say the cam only connected when the SSID and password were set correctly. Note: if the official app can't be used in STA, the credentials have to be set over AP first. — [dashcamtalk A229 WiFi Station Mode](https://dashcamtalk.com/forum/threads/a229-wifi-station-mode.48728/)
- **Viofo [M]:** Stock station mode does not survive a power cycle. The Novatek command `cmd=3033` switches modes (par 0 = AP, par 1 = STA) and needs `cmd=3018` (reconnect) to take effect; one user found STA reset on the next power cycle. — [dashcamtalk A129 access without app](https://dashcamtalk.com/forum/threads/how-to-access-the-a129-over-wi-fi-without-the-viofo-app.37279/)
- **Viofo [M]:** The viofosync project says most users need "Viofo special firmware to keep station mode always-on (supplied by Viofo support on request)". Viofo will hand out STA-persistent firmware if asked. — [RobXYZ/viofosync README](https://github.com/RobXYZ/viofosync)
- **Vantrue N4 Pro [M]:** Stock Vantrue is AP-only and the app connects to the camera's hotspot. The N4 Pro S manual says the cam's Wi-Fi switches on automatically for 10 minutes. — [Vantrue N4 Pro S manual](https://vantrue-app.vantruecam.com/files/manuals/n4pros/Vantrue%20N4%20Pro%20S%20User%20Manual%20English.pdf). Station mode on the N4 Pro is only possible by hacking it: telnet as root with no password at 192.168.1.254, then editing `/usr/share/wifiscripts/down.sh` to run `wpa_supplicant` during parking mode. — [squishdacat/vt-automator](https://github.com/squishdacat/vt-automator). A forum user also found the SSID can't be changed. — [dashcamtalk](https://dashcamtalk.com/forum/threads/can-it-be-changed-the-ssid-name-of-the-vantrue-n4-pro-dashcam.59107/)
- **Garmin [H]:** Garmin's manual covers connecting the camera to a Wi-Fi network through the Garmin Drive app for remote live view and Vault. The remote and Vault features need a paid subscription. — [Garmin manual: Connecting your camera to a Wi-Fi network](https://www8.garmin.com/manuals/webhelp/GUID-8EFC497C-4031-46EE-AC26-B0AE4B3CE8BD/EN-US/GUID-936E4291-28DB-4AEB-845C-8001561318EC.html)
- **BlackVue [H]:** The BlackVue Fleet SDK describes Station Mode (STA) and Access Point Mode (AP) connection protocols. Before SDK 3.0 these required in-vehicle telematics hardware; SDK 3.0 adds Reverse Proxy mode so cameras connect directly to the customer's server. — [BlackVue Fleet SDK search snippet / BlackVue media](https://media.blackvue.com/tag/api). Community tools sync over a LAN with the cam joined to home Wi-Fi. — [acolomba/blackvuesync](https://github.com/acolomba/blackvuesync)
- **70mai [M]:** The local AP sits at 192.72.1.1, and the official app needs a physical button press to authorize. — [geo-chen/70mai](https://github.com/geo-chen/70mai). The A810 with the 4G/SIM module reports GPS, battery voltage and alarms through 70mai's cloud (`eu-api.70mai.com`). — [lorenzo-deluca/homeassistant-70mai](https://github.com/lorenzo-deluca/homeassistant-70mai)
- **Thinkware F800 Pro [M]:** An AP with the default password 123456789 allows only one client device at a time. — [geo-chen/Thinkware-Dashcam](https://github.com/geo-chen/Thinkware-Dashcam). Thinkware Q1000 has built-in Bluetooth 5.0 and the Thinkware Connected app. — [BlackboxMyCar Thinkware compare](https://blackboxmycar.com/pages/compare-thinkware-dash-cams)
- **Nexar [L]:** Nexar markets "instantly upload and access footage from anywhere", meaning the phone app relays footage to Nexar's cloud. — [tflcar Nexar comparison](https://tflcar.com/2024/10/comparing-the-best-dash-cams-nexar-beam2-vs-competitors/)

### Inferences
- For a phone app that must keep cellular data during a drive, **AP mode is a real problem**. iOS joins the cam's SSID with no internet, so Supabase sync and anything else online stalls or falls back to cellular unpredictably. **Viofo STA on the phone's hotspot reverses the roles**: the phone stays online and the cam becomes a LAN client. One snag is that iOS Personal Hotspot gives out addresses in 172.20.10.x and the app has to discover the cam's IP, since there's no mDNS I could confirm.
- [U] 5 GHz: A229 Pro, A329 and A139 Pro are generally sold with 2.4/5 GHz dual-band Wi-Fi; A119 Mini 2 is likely 2.4 GHz only. I did not confirm this on spec pages.
- [U] Bluetooth: A229 Pro, A329 and Garmin X-series include BLE for app pairing and remote buttons. I found no evidence that any BLE channel carries video or events to third parties.

### Gaps
- 5 GHz and Bluetooth spec confirmation for every model. I fetched no spec pages, by choice, to stay inside the tool budget.
- Rove R2/R3 and Redtiger: no sources found. [U] Both are believed to be Novatek/AP-only cams that likely answer the 192.168.1.254 command set, but this is unconfirmed.
- Garmin X-series (X110/X210/X310) Wi-Fi details: whether "connect to a Wi-Fi network" is real STA or only for Vault upload.
- Whether Viofo's 2025–2026 app now supports STA (the open question in the 2026-01 forum post).

## Q2: Which cams have documented or community-documented HTTP/RTSP APIs: Novatek commands, live streams, file lists and downloads, and GPS or G-sensor data in the files?

### Takeaway
Viofo, any Novatek-based cam (Viofo, likely Vantrue, Rove, Redtiger and many no-name brands) and BlackVue all have mature, actively maintained community APIs (2026 commits). Viofo has the best tooling. Viofo clips can be GPS-triaged over HTTP Range requests without downloading the whole clip. 70mai and Thinkware expose unauthenticated RTSP and HTTP, documented mainly in security disclosures.

### Cited Findings
- **Novatek command API [M]:** The format is `http://192.168.1.254/?custom=1&cmd=<n>&par=<p>&str=<s>` and replies come back as XML. `cmd=3012` returns the firmware version. `cmd=3002` lists the commands the device supports (not all of them work). `cmd=3033` toggles AP/STA and `cmd=3018` reconnects. Command constants can be pulled by decompiling the Viofo Android app or sniffing its traffic, and an old Novatek NT9666x Wi-Fi API PDF circulates. — [dashcamtalk A129 thread](https://dashcamtalk.com/forum/threads/how-to-access-the-a129-over-wi-fi-without-the-viofo-app.37279/)
- **Viofo file list [H, code]:** viofosync, a maintained 2026 project, lists recordings with `GET {base}/?custom=1&cmd=3015&par=1` and falls back to scraping the HTML directory index. It parses Viofo filename suffixes `F/R/T/I` (front/rear/telephoto/interior). Tested on A139 Pro, A229 Plus, A229 Pro, A329 and A329S. — [viofosync `_protocol.py`](https://github.com/RobXYZ/viofosync/blob/main/viofosync_lib/_protocol.py), [README](https://github.com/RobXYZ/viofosync)
- **Viofo GPS without downloading [H, code]:** viofosync's `open_remote_reader` / `extract_remote_gps_points` decode a clip's embedded GPS track using HTTP `Range: bytes=a-b` reads of the moov atom. The camera closes the socket per request, and the code also handles servers that ignore Range and send the whole body. Its "GPS triage" pulls a clip's track "in seconds". It also reads and changes camera settings, with destructive actions blocked. — [viofosync `_protocol.py`](https://github.com/RobXYZ/viofosync/blob/main/viofosync_lib/_protocol.py)
- **Viofo live stream [M]:** RTSP at `rtsp://192.168.1.254` (AP) or `rtsp://<IP>` (STA) works in VLC on PC but not in some Android players. — [dashcamtalk A229 RTSP](https://www.dashcamtalk.com/forum/threads/a229-rtsp-wifi-station.49563/). On the MT1, RTSP didn't work but an HTTP MJPEG stream at `http://192.168.1.254:8192` did. — [dashcamtalk A129 thread](https://dashcamtalk.com/forum/threads/how-to-access-the-a129-over-wi-fi-without-the-viofo-app.37279/). Viofo officially documents `rtsp://<IP_ADDRESS>` live view in STA. — [Viofo blog](https://www.viofo.com/blogs/viofo-car-dash-camera-guide-faq-and-news/how-to-enable-wi-fi-station-mode-on-your-viofo-dashcam)
- **Novatek GPS-in-MP4 [M]:** GPS is stored in MP4 `free` atoms. A `gps ` descriptor points at fixed-size atoms, and in one variant each holds a `GPS ` magic plus a payload XOR'd with `0xAA`. Coordinates come in DDDmm.mmmm and need converting. — [ZanardiZZ/novatek-gps-parser (2026)](https://github.com/ZanardiZZ/novatek-gps-parser); [Sergei Franco nvtk_mp42gpx.py gist](https://gist.github.com/UndeRus/01ef8b436353f579760a60b0dea96253). Viofo changed the GPS format around firmware 2.0, which broke older scripts. — [dashcamtalk script thread](https://dashcamtalk.com/forum/goto/post?id=298694). ExifTool supports three embedded GPS formats. — [ExifTool forum](https://exiftool.org/forum/index.php?msg=45477). Other parsers: [miahi/a119_join](https://github.com/miahi/a119_join), [davidar/novatek-mapillary (Vantrue and others)](https://github.com/davidar/novatek-mapillary), [minusbrain/vantrue2gpx](https://github.com/minusbrain/vantrue2gpx).
- **Vantrue [M]:** It is Novatek-style at 192.168.1.254, with telnet as root and no password, plus FTP, on the N4 Pro. — [vt-automator](https://github.com/squishdacat/vt-automator). GPS can be extracted by vantrue2gpx and novatek-mapillary (links above).
- **BlackVue local API [M]:** The AP is at `10.99.77.1:80`. Endpoints: `/blackvue_vod.cgi` (SD-card file list), `GET /<path>` (download), `/blackvue_live.cgi?direction=F|R` (live front/rear), `/Config/version.bin`, `/Config/config.ini`, `/upload.cgi` (config and firmware upload). — [johnhamelink/blackvue wiki](https://github.com/johnhamelink/blackvue/wiki). blackvuesync 2.2.0 supports "the new API in BlackVue firmware V1.009+", so the API changed in recent firmware. — [acolomba/blackvuesync](https://github.com/acolomba/blackvuesync). The Node `blackvue` package streams live JPEG frames and lists and downloads files. — [unpkg blackvue@1.0.3](https://app.unpkg.com/blackvue@1.0.3/files/index.js). BlackVue MP4s carry GPS and acceleration (G-sensor) data that [gandy92/blackclue](https://github.com/gandy92/blackclue) extracts. Multiple CVEs exist for the DR750 local API. — [eyJhb/blackvue-cve-2023](https://github.com/eyJhb/blackvue-cve-2023)
- **70mai [M]:** Files are at `http://192.72.1.1/SD/Normal/<file>` with no HTTP auth, RTSP is at `rtsp://192.72.1.1/liveRTSP/av4` (port 554), and settings go through `/cgi-bin/Config.cgi?action=set&property=...`. That URL pattern looks like the Ambarella/"Camera.Menu" family, not Novatek. — [geo-chen/70mai](https://github.com/geo-chen/70mai). M300 CLI: [XuZhen86/70MaiM300Toolbox](https://github.com/XuZhen86/70MaiM300Toolbox). The 70mai GPS extractor is [dexterxx-pl/70mai-gps-extractor](https://github.com/dexterxx-pl/70mai-gps-extractor), and custom A810S firmware exists at [350d/70Mai_A810S_Firmware](https://github.com/350d/70Mai_A810S_Firmware).
- **Thinkware [M]:** On the F800 Pro, RTSP on port 554 and telnet on port 23 give access to video with no pairing, using the default Wi-Fi password. Disclosed to Thinkware in Nov 2024. — [geo-chen/Thinkware-Dashcam](https://github.com/geo-chen/Thinkware-Dashcam). A Python library in early development has only the F800 tested. — [K4LCIFER/snakeware](https://github.com/K4LCIFER/snakeware)
- **Garmin [L]:** No public API or reverse-engineering writeup for Garmin dash cams. A dashcamtalk developer notes that major manufacturers ship apps but "not an official SDK". The only Garmin precedent is the VIRB action cam's HTTP/JSON+RTSP API, a different and discontinued product line. — [dashcamtalk dev thread](https://dashcamtalk.com/forum/threads/interfacing-my-app-with-a-dash-cam-and-develop-cloud-related-features.43649), [Garmin VIRB API forum](https://forums.garmin.com/apps-software/apps-software-archive/f/virb-edit-windows/70831/virb-elite-wireless-api/731996)

### Inferences
- A Capacitor iOS app can talk to a Viofo with plain HTTP from native code: `cmd=3015` for the list, Range reads for GPS, a GET for clip download. It will need an ATS exception or the local-network permission (`NSLocalNetworkUsageDescription`) because the cam serves cleartext HTTP. That needs native plugins or `CapacitorHttp`, since WebView fetch to cleartext LAN IPs is restricted.
- **Live in-app video is hard on iOS.** RTSP isn't playable in AVPlayer or WKWebView, so it needs an FFmpeg/VLCKit-based native player, and an MJPEG fallback where offered. For a driving-score app, **post-drive clip and GPS pull is the realistic path**. Live RTSP is a stretch goal.
- The Novatek command set varies by model and firmware. Use `cmd=3002` at runtime to discover which commands a cam supports rather than hardcoding them.
- Novatek GPS-in-MP4 gives a 1 Hz GPS track, which matches the app's GPS. [U] Viofo files may also embed G-sensor values, but I did not confirm this. BlackVue clearly embeds accelerometer data.

### Gaps
- The full Viofo command map. viofosync has `scripts/build_command_map.py`, which I did not read.
- RTSP stream paths for the rear channel, and their latency on Viofo.
- Whether Viofo MP4s embed G-sensor samples, or only GPS and speed.

## Q3: Cloud APIs, SDKs and partner programs: BlackVue, Nexar, Garmin, Thinkware, and fleet cams as reference points

### Takeaway
Among consumer brands, only BlackVue has a real developer program: the Fleet SDK 3.0, now with no NDA and a test server. It works through custom firmware, its sample app is Android-only, and access starts with a sales contact. Nexar, Garmin, Thinkware and 70mai have no public API; 70mai's cloud is used unofficially. The fleet vendors (Lytx, Samsara, Motive) have proper video APIs but are B2B-only and need their hardware plus a fleet contract, so they're no use to an indie consumer app.

### Cited Findings
- **BlackVue Fleet SDK 3.0 [H]:** Supports the DR770X family, including the 2CH, IR, DMS, 1CH, LTE and BOX variants. Adds Reverse Proxy mode so cams connect directly to the developer's servers. Exposes live video, GPS and event notifications. The NDA was removed for new applicants and a test server exists for Reverse Proxy. You apply through a form or sales@pittasoft.com and receive docs, pricing and an SDK kit that includes a dash cam with dedicated firmware. The custom firmware does not support BlackVue Cloud, and the sample app is Android-only. — [BlackVue media: API tag](https://media.blackvue.com/tag/api); [blackvue.com/fleet-sdk (returned 404 on fetch; details from search snippets)](https://blackvue.com/fleet-sdk/)
- **BlackVue Cloud API [M]:** BlackVue announced a Cloud API for fleet telematics integration, and its business page says the Cloud API is "being overhauled", with integration questions going to sales. — [EDACafe press release](https://edacafe.com/nbc/articles/1/1618702/BlackVue-Introduces-Cloud-API-Facilitate-Fleet-Telematics-Software-Integration); [blackvue.com/business](https://blackvue.com/business/). The community Cloud API section is unwritten. — [johnhamelink wiki](https://github.com/johnhamelink/blackvue/wiki)
- **Nexar [L]:** No public developer API found. Its data business is B2B: anonymized road data (CityStream Work Zones API), plus training datasets offered to enterprises. Consumers can share clips with family or insurers inside the app. — [Wikipedia: Nexar](https://en.wikipedia.org/wiki/Nexar); [Nexar Connect App Store](https://apps.apple.com/us/app/nexar-connect/id6478313031)
- **Garmin [L]:** No dash-cam SDK found; see Q2. Remote and Vault features need a subscription. — [Garmin manual](https://www8.garmin.com/manuals/webhelp/GUID-8EFC497C-4031-46EE-AC26-B0AE4B3CE8BD/EN-US/GUID-936E4291-28DB-4AEB-845C-8001561318EC.html)
- **70mai cloud [M]:** An undocumented cloud API at `eu-api.70mai.com` is used by a Home Assistant integration for GPS position, battery voltage and alarms. It needs the 4G module and is confirmed only on the A810, and it is "not affiliated… can change without notice". — [homeassistant-70mai](https://github.com/lorenzo-deluca/homeassistant-70mai)
- **Lytx [H]:** A public developer portal with a Video (DriveCam) API: list vehicles, check video availability, create events, get a media URL per event view, and snapshot at a given time. Bearer-token auth, plus webhooks. — [Lytx Developer Portal](https://developer.lytx.com/openapi/video/tag/Video-(DriveCam)); [Getting started](https://developer.lytx.com/docs/gettingstarted)
- **Samsara [H]:** `POST` and `GET cameras/media/retrieval` are GA. Video can only be retrieved after a trip ends, the cam and the Vehicle Gateway must both be online, and requests are quota-limited. HRV covers clips under 1 minute; hyperlapse covers longer ones. — [Samsara changelog](https://developers.samsara.com/changelog/post-camerasmediaretrieval-generally-available); [Samsara KB](https://kb.samsara.com/hc/en-us/articles/26516176169613)
- **Motive [H]:** API-triggered dashcam JPEG capture went GA on 2026-06-02 for AI Dashcam, AI Dashcam Plus and Omnicam. It takes a still only, no video. — [Motive help center](https://helpcenter.gomotive.com/hc/en-us/articles/36541567575709-Dashcam-Image-capture-via-API)

### Inferences
- The fleet APIs are a useful design reference for the app's own Supabase schema (event → media URL → snapshot), and they confirm that even the best APIs deliver video **after the trip**, not live.
- For an indie developer, the BlackVue Fleet SDK is the only sanctioned path with live, GPS and event data. It ties you to custom firmware that drops BlackVue Cloud, and the sample app is Android-only, so expect B2B pricing and friction for consumer users. That's poor for a consumer app, where users run stock firmware.

### Gaps
- Nauto, Raven and Owl Cam developer offerings: no results in this pass. [U] Owl Cam was discontinued around 2022–23, and Raven was pivoting to fleet.
- Thinkware Connected cloud API: none found. BlackVue Fleet SDK pricing is not public.

## Q4: Which cams raise ADAS events on the camera (forward collision, lane departure, front-car-start, speed cameras), and can a third party read those events?

### Takeaway
I found no source showing that a third party can read on-camera ADAS events from any consumer cam. The only machine-readable event channels are BlackVue Fleet SDK "event notifications", 70mai cloud "alarms" (unofficial), Viofo "locked/event" files (G-sensor or manual, shown by folder or filename), and event files in BlackVue's file list.

### Cited Findings
- BlackVue Fleet SDK exposes "event notifications". — [BlackVue media](https://media.blackvue.com/tag/api)
- 70mai's cloud exposes alarms as Home Assistant binary sensors (A810 + 4G). — [homeassistant-70mai](https://github.com/lorenzo-deluca/homeassistant-70mai)
- viofosync can filter "locked (event) clips only", so a third party can tell event clips apart through the file list. — [viofosync README](https://github.com/RobXYZ/viofosync)
- Viofo discussed an auto-upload feature for the A329S/T: when locked files exist, the cam turns on STA, connects to a hotspot, uploads (FTP to a server; "all files" supported), then turns Wi-Fi off. Users questioned the trigger, and I could not confirm it shipped. — [dashcamtalk A329S/T auto upload](https://dashcamtalk.com/forum/threads/automatically-uploading-files-feature-on-a329s-t-do-you-need-it.54150/). An A139 user said auto-upload covered event files only, as a 480p substream. — [search summary of dashcamtalk A139 Firmware thread](https://dashcamtalk.com/forum/threads/a139-firmware.43578/post-553409) [L]
- Thinkware U3000 has a built-in radar detector. — [BlackboxMyCar compare](https://blackboxmycar.com/pages/compare-thinkware-dash-cams)

### Inferences
- [U] ADAS features in the Garmin X-series (FCW, LDW, "Go" alert), Thinkware (FCWS/LDWS/FVDW, speed-cam alerts in the U3000/Q1000 with safety-camera updates), 70mai A810/A510 (ADAS) and Vantrue are voice or screen alerts only. None of them are logged anywhere a third party can reach. Viofo cams mostly don't do ADAS beyond GPS speed-cam alerts in some regions.
- The app's own GPS and IMU events are a better source than cam ADAS anyway. Align them to the cam's clips by timestamp and embedded GPS.

### Gaps
- No confirmed per-model ADAS feature list (spec pages not fetched). No evidence either way on whether ADAS triggers are written to file metadata.

## Q5: Price, and the best single model for an indie developer today

### Takeaway
**Viofo A229 Pro 2CH, with the A329 as an upgrade.** It has official station mode and official RTSP, an active 2026 open-source stack (viofosync, dashcam-transporter, Home Assistant add-on), a decoded GPS-in-MP4 format with Range-read triage, and Viofo will hand out always-on-STA firmware. The A139 Pro is a cheaper screenless option but its IP is harder to find. BlackVue DR770X is second: a good local API plus the only official SDK, but more expensive and a different chipset/API family that recently changed with firmware 1.009.

### Cited Findings
- Thinkware U3000 is about $459.99 (U3000 Pro about $499.99), July–August 2026 aggregator listings. — [frontdeskreview U3000 Pro](https://frontdeskreview.com/product/dash-cams/thinkware-u3000-pro/)
- Garmin Dash Cam X310 is $399.99. — [frontdeskreview X310](https://frontdeskreview.com/product/dash-cams/garmin-dash-cam-x310/); [B&H dash cams](https://www.bhphotovideo.com/c/buy/dashboard-cameras/ci/27316/pn/4)
- Viofo A229 Pro is the confirmed target of dashcam-transporter, and viofosync is tested on A229 Pro/Plus, A329/A329S and A139 Pro. — [steve192/dashcam-transporter](https://github.com/steve192/dashcam-transporter); [viofosync](https://github.com/RobXYZ/viofosync)

### Inferences
- [U] Approximate US street prices, all unconfirmed: Viofo A229 Pro 2CH about $250–300, A229 Plus 2CH about $170–200, A329 2CH about $350–400, A139 Pro 2CH about $200–250, A119 Mini 2 about $90 (front only); BlackVue DR970X-2CH about $450–500 and the LTE variant higher; Vantrue N4 Pro about $250–300; 70mai A810 about $150–200; Nexar One about $200–300 with subscriptions. Verify all of these before quoting them.
- Suggested build: (1) the iOS app keeps the Personal Hotspot on and the Viofo runs STA firmware, joining the phone. (2) After the drive, the app discovers the cam's IP, calls `cmd=3015`, Range-reads GPS from each clip, and matches clips to the app's own events by time and location. (3) It downloads only the short clips around harsh events and uploads them to Supabase Storage. RTSP live preview can come later, through a native VLCKit/FFmpeg plugin.

### Gaps
- I verified no live Viofo, BlackVue, 70mai or Nexar prices. Nexar's compare page redirected and was not re-fetched. The Rove and Redtiger price and API status is unknown.
