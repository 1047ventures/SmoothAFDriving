Home Screen Audit

Every element on the home screen, sorted by what should happen to it. Grouped by verdict rather than by position, because the useful question is what needs deciding — not what sits nearest the top.

Reviewed Aug 16, 2026 · against build 118

If it’s on the home screen it should open something on tap. If there’s nothing worth opening, it shouldn’t be competing for the space.

That cuts both ways, which is what makes it useful as a test rather than a to-do list.

Needs a decision

2 · product calls

Neither of these is a bug or an oversight. Both are features that were started and never finished, and the rule catches them precisely because half-built things fail it.

Finish or cut
“Driving Trends” sparkline
A chart you can’t interrogate. It draws a real line from real drives, then refuses to explain any of it. Either tapping it opens a trends view worth the space, or the space goes to something that earns it.
Finish or cut
The persona block home-persona-title · home-persona-sub · home-unlock-text
Hidden with inline display:none, but the code still writes content into all three every render. A feature that computes something nobody can see. Reviving it and deleting it are both defensible; leaving it is the one option that isn’t.

Give it somewhere to go

6 · straightforward

These already carry information the driver would reasonably want to pull on. None needs a new concept — most have a destination that already exists.

What the audit actually found

Applied strictly, the rule doesn’t produce a list of eight tap targets to bolt on. It produces two unfinished features and one corpse. The elements that fail hardest aren’t clutter — they’re the sparkline and the persona block, both of which were built partway and left. The linking work is a couple of hours; the decision about those two is the audit.
